# AutoUpdate app connector contract v1

The common updater stores immutable, verified package versions and atomically changes one `current.json` pointer per app. The app reads the selected version from the returned package path. Before loading or activating any package content, call `Get-AuVerifiedCurrent`; it verifies the current pointer against the manifest and rechecks every payload size and SHA-256. A missing, altered, or inconsistent package is rejected. It must never execute files from the shared source checkout or from a staging directory.

Each connector supplies its stable `app_id`, platform architecture, writable per-user `StateRoot`, current app version, and the hooks `canApplyLive/deferReason`, `prepareLive`, `commitLive/rollbackLive`, `saveUiState/restoreUiState(schema)`, `onUpdateConfirmed`, and `onUpdateFailed`. The current core exposes `Install-AuPackage`, `Get-AuCurrent`, and `Get-AuVerifiedCurrent`; the connector remains responsible for app-specific UI state and the actual live/restart boundary.

Live submarine patching is the default. If a package omits `mode`, both the core and packager select `live` for data/resources and `restart` only when executable/runtime files make an in-place change unsafe. For a `live` package, every entry must be data or a resource, and the app must declare the compatible schema and a safe activation point. The connector switches resources as a complete set and keeps the current process, windows, unsaved input, timers, and work state intact. A package containing executable or updater-runtime code cannot be marked `live`. A live package is prepared and fully verified before activation; `canApplyLive` may defer it until an app-defined safe point, keeping the old complete set active.

For a `restart` package, the app first captures and durably writes its UI/work state, then asks the updater helper to apply it after normal shutdown. The updated program reopens the exact prior screen and restores settings, draft input, selected tab, scroll/focus, and in-progress state before acknowledging health. Only then may the previous executable be retired. If startup or restoration fails, return to the previous version and state. User settings, credentials, cache, and user data are outside package paths.

The engine core is loaded by versioned path, not copied into each app. Updating the common engine installs a new immutable engine version and switches its pointer. Connectors reload it at a safe update boundary. An app needs a one-time connector integration; existing apps without it do not receive common-engine changes automatically.

The package schema uses SHA-256 and an explicit publisher policy. Production downloads must come from the configured GitHub release API over validated HTTPS; credentials are read from Windows Credential Manager and are never included in app configuration, arguments, logs, or package files. File/temporary package installation is reserved for local verification.

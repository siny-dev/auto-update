# AutoUpdate 공용 패치 기반

공유 경로: \\H255\AI-Work\제작중인 프로그램\AutoUpdate

## 목표

공용 업데이트 엔진을 여기서 한 번 수정하고, 해당 엔진에 등록된 프로그램들이 각자의 안전한 업데이트 주기에 새 호환 패치를 받게 한다. 공용 엔진 배포와 각 앱의 패키지 수신·적용은 각각 별도 상태로 기록한다.

## 원칙

- 소스 기준은 이 폴더의 Git 이력으로 관리하고, GitHub와는 정해진 주기로 동기화한다.
- 로컬과 원격의 변경을 커밋 그래프로 비교한다. 한쪽이 다른 쪽의 조상이면 안전한 방향으로 동기화하고, 분기·삭제·이름 변경 충돌은 양쪽 자료를 보존한 채 멈춘다. 강제 덮어쓰기는 하지 않는다.
- 앱은 공유 소스 폴더의 임의 파일을 실행하지 않는다. 검증된 버전 패키지를 앱별 staging에 받고, 앱 ID·플랫폼·호환성·크기·SHA-256을 확인한 뒤에만 적용한다.
- 호환 데이터와 리소스는 앱이 허용한 안전 시점에 live 적용한다. 실행 코드 변경은 현재 앱의 계약이 허용하지 않으면 상태를 저장하고 재시작 경로로 처리한다.
- 실패 시 직전 정상본과 사용자 설정을 보존하고 복구한다. 현재 버전, 준비 버전, 적용 버전을 구분한다.
- 토큰·로그인 세션·사용자 데이터·로컬 설정·캐시·빌드 산출물은 동기화 대상과 저장소에서 제외한다. 인증정보는 Windows 자격 증명 관리자에 둔다.
- AutoUpdate 변경을 앱에 반영하려면 공용 런타임뿐 아니라 앱별 얇은 연결부와 호환 계약이 필요하다.

## 디렉터리

- source/: 공용 런타임 소스
- contracts/: 앱 연결부, manifest 및 호환 계약
- packages/: 버전별로 검증·발행된 런타임 패키지
- channels/stable/, channels/canary/: 배포 채널 포인터
- outbox/: 오프라인 수정의 커밋·동기화 대기 정보
- state/, logs/: 이 PC의 동기화 상태와 진단 기록. Git에 올리지 않는다.

## 기존 기반과 마이그레이션

app-base에는 live 리소스 적용, 재시작 helper, 화면 상태 복원 및 실패 복구 기반이 있고, github-auto-maker는 새 앱을 만들 때 그 기반을 복사한다. 새 앱은 이 공용 계약을 기본 연결하고, 기존 앱은 한 번씩 연결부를 적용·검증해야 한다. 첫 적용은 PC 앱에서 canary로 확인한 뒤 안정 채널에 넓힌다. MA는 적용 범위에서 제외한다.

## 현재 상태

이 폴더에는 로컬/원격 커밋 그래프를 비교하는 숨김 동기화 작업자(tools/sync.ps1)와 Windows 자격 증명 관리자에서만 PAT를 읽는 Git helper가 준비되어 있다. 로컬 임시 저장소에서 단방향 push, fast-forward pull, 분기 충돌 보존을 확인했다. 아직 이 폴더의 GitHub 원격 저장소, 쓰기 가능한 전용 자격 증명, 자동 실행 등록, 앱별 연결부는 구성되지 않았다. 따라서 현재 공유폴더 파일만으로 앱 패치나 실시간 GitHub 동기화가 작동하는 상태는 아니다.
